📘 手册实战通用开发流程

把公司产品开发手册的方法论提炼成不依赖特定公司的通用开发流程。手册是流程骨架，监管制度是内容标准——两者冲突时一律以监管制度为准（本站第一裁决规则）。

二 · 手册最容易过时的六个点（对照自查）

手册更新慢于监管发文是常态。翻手册时先对照查这六个点：

检查点手册可能还在写现行口径
经验生命表生命表2010-2013（已废止）生命表2025，2026-01-01起（金规〔2025〕21号）
预定利率上限3.5% / 3.0% / 2.5% 旧值普通 2.0% / 分红 1.75% / 万能最低保证 1.0%（2025-09起，动态调整机制下以最新为准）
分红利益演示低/中/高三档利差法（93号旧口径，已废止）两档演示：银保监规〔2022〕24号改为保证利益演示+红利利益演示，利差 ≤ 0 / 4.5%−产品预定利率；红利上限公式 (V₀+P)×利差×70%（银保监办发〔2020〕6号）+ 演示利率上限 3.5%（2026-07起）
信息披露2009年第3号令体系2022年第8号令 + 24号规则（含分红实现率年度披露）
渠道费用「佣金另议」「费用弹性」类表述报行合一：附加费用率=可用总费用水平（66号），费用分摊按86号指引
假设管理假设仅存档、无验证回溯环节假设设定→验证→回溯全流程管理（金办便函〔2026〕616号）
裁决规则再申明：手册的价值在流程、模板、内部职责划分——这些继续用；涉及数字与口径（表、利率、演示、披露）的部分，一律以本站各专页与监管原文为准。

三 · 手册方法论核心：假设管理导向的闭环

现行产品开发方法论的主流方向，是从「以报备为中心」走向「假设管理导向的闭环」——本站导航仪、自查表、案例均按此组织：

  • 流程闭环：立项 → 报备 → 上市 → 回溯，回溯结论反哺下一代产品的假设设定，而不是走完即止。
  • 假设全流程管理（616号）：定价即考虑回溯，上市即开始监控——假设不是「写完存档」，而是设定→验证→回溯的连续动作。
  • 费用真实性内嵌（报行合一）：渠道费用在立项与设计阶段就锁定，不留「事后调整」空间。
  • 动态参数思维：预定利率跟踪研究值、发生率跟踪经验偏差、演示利益跟踪分红实现率——参数是活的，手册里的静态数字要按季核对。
  • 与导航仪开发自查表 7 里程碑一一对应，可直接作为项目管理的检查框架。

四 · 常见手册流程问题的「制度答案」

手册说「精算报告写完再定费率表」——顺序对吗？
方向没错但容易返工。费率表、现金价值表、精算报告假设三者必须同源（负面清单：四套材料不一致是驳回高发点）。实操建议：假设表先行锁定 → 费率/现价表生成 → 精算报告引用 → 说明书演示最后核对（对照红利上限公式与演示利率上限）。
手册的内部审批链与监管报送时限冲突怎么办？
内部流程让路外部时限。3号令体系下备案/审批有时限与补正要求，监管时限是硬约束；内部审批链按手册走，但建议手册中预留「绿色通道」条款（监管沟通、限时补正场景）。
手册模板里的「产品可行性分析」要不要包含资本占用？
现行方法论下必须包含：偿付能力占用（分红/年金类尤其显著）与利润口径（新业务价值、利润率）并列。能定价 ≠ 能卖——资本占用超预算的立项应该在阶段1/2就被拦下，而不是报备后才发现。
回溯发现假设偏差，手册流程到哪一步？
按616号全流程管理：偏差分析（发生率/费用/退保/利率分维度）→ 假设修正决议 → 纳入下一代产品与存量评估 → 回溯记录归档。意外险（106号）与互联网产品（1275号）另有专项回溯报告义务。

⚖️ 制度冲突裁决规则（全站适用）

  1. 监管制度 > 工作手册：手册内容仅作流程性参考，与制度冲突时以制度为准。
